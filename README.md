# MyHealthy — ระบบห้องพยาบาลแบบ Real-time

## คุณสมบัติ
- นักเรียนแจ้งอาการ ติดตามสถานะ ดูประวัติ และ**ยกเลิกคำขอของตัวเองได้**ตราบใดที่ยังไม่ถูกนัด
- ครูเข้าสู่ระบบด้วย **username + password + รหัสเข้าใช้งานพิเศษ (Access Code)** ที่ใช้ร่วมกันเฉพาะบุคลากร เพื่อกันไม่ให้คนอื่นเดา/ลองรหัสผ่านสุ่มเข้ามาได้
- Real-time ผ่าน WebSocket ใช้งานข้ามเครื่องในเครือข่ายเดียวกันได้
- สถานะคิว: PENDING → SCHEDULED → ARRIVED → COMPLETED (หรือ REJECTED / CANCELLED)
- แสดงข้อมูลแพ้ยาก่อนจัดการเคสเสมอ
- ระบบช่วยประเมินอาการ (Decision Support ไม่ใช่การวินิจฉัย) เรียงตามลำดับความสำคัญ
- ครูสามารถ**ปิดเคสแบบไม่จ่ายยา**ได้ (แจ้งซ้ำ/แจ้งผิด) พร้อมเหตุผล
- บันทึกการจ่ายยาและ Audit Log ทุกการกระทำสำคัญ
- คลังยาแก้ไขได้จากหน้าครู (เพิ่ม/นำออก) โดยไม่ต้องแก้ฐานข้อมูลเอง **และตอนนี้เพิ่ม/แก้ "อาการที่ใช้ยานี้ได้" ด้วย checkbox จากรายการอาการเดียวกับที่นักเรียนแจ้ง (กันสะกดไม่ตรง/สับสน — ไม่มีช่องพิมพ์อาการเองที่ไหนเลย)**
- ตอนจัดการเคส ยาที่ **ตรงกับอาการที่นักเรียนแจ้ง** จะถูกจัดเรียงขึ้นก่อนและมีป้าย ✅ กำกับ แยกจากป้าย ⚠️ เตือนแพ้ยา (คนละเรื่องกัน ยาที่ตรงอาการก็ยังอาจแพ้ได้)
- สร้างข้อความแจ้งผู้ปกครองหลังปิดเคส **และมีแท็บ "📨 แจ้งผู้ปกครอง" ให้ครูตรวจทาน แก้ไข แล้วกดอนุมัติ/ไม่ส่งจริง** (ของเดิมสร้างข้อความค้างไว้เฉยๆ ไม่มีที่ให้ดู — จุดนี้แก้ไขแล้ว)
- **เมื่อกดอนุมัติข้อความ ระบบจะส่งข้อความหาผู้ปกครองผ่าน LINE Messaging API ให้อัตโนมัติทันที** ถ้านักเรียนคนนั้นมี LINE User ID ของผู้ปกครองผูกไว้แล้ว (ผูกได้จากปุ่ม "🔗 ตั้งค่า LINE ผู้ปกครอง" ในหน้าจัดการเคส) — ถ้ายังไม่ได้ผูก หรือส่งไม่สำเร็จ ระบบจะแจ้งเตือนครูให้ส่งเองแทน ไม่ทำให้การอนุมัติล้มเหลว
- Session ถูกเก็บไว้จนกว่าจะกด "ออกจากระบบ" เท่านั้น ไม่มีการล็อกเอาต์อัตโนมัติ

## แก้ไขจุดที่ไม่เหมาะสมจากเวอร์ชันก่อนหน้า (สำคัญ)
1. **ช่องโหว่ร้ายแรง:** เดิมเส้นทาง `/<path:p>` เสิร์ฟไฟล์ *ใดก็ได้* ในโฟลเดอร์โปรเจกต์ หมายความว่าใครก็ตามที่รู้ URL สามารถดาวน์โหลด `app.py`, `db_setup.py`, `requirements.txt` และที่ร้ายแรงที่สุดคือ **`myhealthy.db`** (มีรหัสผ่านที่ถูกแฮช, token การเข้าสู่ระบบ, และข้อมูลสุขภาพ/การแพ้ยาของนักเรียนทุกคน) ได้โดยตรงผ่านเบราว์เซอร์ — แก้แล้วโดยจำกัดให้เสิร์ฟเฉพาะไฟล์หน้าเว็บ (.html/.css/.js/รูปภาพ/ฟอนต์) เท่านั้น
2. ข้อความแจ้งผู้ปกครองที่สร้างหลังปิดเคสไม่เคยถูกแสดงที่ไหนเลย (ค้างในฐานข้อมูลตลอดไป) — เพิ่ม endpoint และแท็บให้ครูตรวจทาน/แก้ไข/อนุมัติหรือยกเลิกได้จริง
3. นักเรียนไม่มีทางยกเลิกคำขอที่พิมพ์ผิดหรือหายแล้วได้เอง ต้องรอครู — เพิ่มปุ่มยกเลิก (เฉพาะตอนยังเป็น PENDING)
4. ครูไม่มีทางปิดเคสที่เป็นการแจ้งเตือนผิด/ซ้ำได้ นอกจากปล่อยค้างหรือฝืนกดจ่ายยา — เพิ่มสถานะ REJECTED พร้อมเหตุผล
5. คลังยาต้องแก้ผ่าน `db_setup.py` เท่านั้น — เพิ่ม UI ให้ครูเพิ่ม/นำยาออกจากหน้าเว็บได้เลย
6. เพิ่ม index ในฐานข้อมูลสำหรับคอลัมน์ที่ใช้กรอง/ค้นหาบ่อย (status, student_id) เพื่อรองรับข้อมูลจำนวนมากในระยะยาว

## สร้างบัญชีครูครั้งแรก (ตอนนี้ต้องตั้ง "รหัสเข้าใช้งานพิเศษ" ด้วย)
รหัสเข้าใช้งานพิเศษ (accessCode) คือรหัสกลางที่บุคลากรห้องพยาบาลทุกคนใช้ร่วมกัน แยกต่างหากจากรหัสผ่านส่วนตัว — ต้องกรอกทุกครั้งที่ล็อกอินหน้าเว็บครู เพื่อกันไม่ให้นักเรียนที่บังเอิญเห็น/เดารหัสผ่านของครูคนใดคนหนึ่งเข้าระบบได้

หลังรัน Server แล้ว ใช้ PowerShell:
```powershell
Invoke-RestMethod -Method POST http://localhost:5000/api/bootstrap-teacher -ContentType "application/json" -Body '{"username":"teacher","password":"CHANGE_THIS_PASSWORD","accessCode":"CHANGE_THIS_CODE","displayName":"ครูห้องพยาบาล"}'
```
หรือ macOS/Linux ใช้ curl:
```bash
curl -X POST http://localhost:5000/api/bootstrap-teacher -H "Content-Type: application/json" \
  -d '{"username":"teacher","password":"CHANGE_THIS_PASSWORD","accessCode":"CHANGE_THIS_CODE","displayName":"ครูห้องพยาบาล"}'
```
จากนั้น Login ที่ `teacher.html` ด้วย username, password และ accessCode ที่ตั้งไว้

**เปลี่ยนรหัสเข้าใช้งานพิเศษภายหลังได้** (เช่น ทุกภาคเรียน หรือทันทีที่สงสัยว่ารั่วไหล) โดยล็อกอินแล้วเรียก:
```bash
curl -X POST http://localhost:5000/api/teacher/access-code -H "Content-Type: application/json" \
  -H "Authorization: Bearer <TOKEN>" -d '{"currentPassword":"...","newAccessCode":"..."}'
```

## ตั้งค่า LINE Messaging API (แจ้งผู้ปกครองอัตโนมัติ)
ฟีเจอร์นี้เป็นทางเลือก — ถ้าไม่ตั้งค่า ระบบจะทำงานเหมือนเดิมทุกอย่าง (ครูคัดลอกข้อความไปส่งเอง) เพียงแต่จะไม่มีการส่งอัตโนมัติเกิดขึ้น

1. สร้าง Messaging API Channel ใน [LINE Developers Console](https://developers.line.biz/console/) แล้วคัดลอก **Channel access token (long-lived)**
2. ตั้งเป็น environment variable บนเครื่อง/เซิร์ฟเวอร์ที่รัน `app.py` (**ห้ามใส่ในไฟล์โค้ดหรือฐานข้อมูลเด็ดขาด**):

   macOS/Linux:
   ```bash
   export LINE_CHANNEL_ACCESS_TOKEN="ใส่ token ที่นี่"
   python app.py
   ```
   Windows PowerShell:
   ```powershell
   $env:LINE_CHANNEL_ACCESS_TOKEN="ใส่ token ที่นี่"
   python app.py
   ```
3. ให้โรงเรียนประชาสัมพันธ์ให้ผู้ปกครองแอด LINE Official Account ของโรงเรียน (ตัว OA เดียวกับที่ผูกกับ Channel ในข้อ 1) แล้วส่ง **LINE User ID** ของตัวเองกลับมาให้ครู (เช่น ผ่านฟอร์มตอนต้นเทอม หรือทัก OA แล้วให้ระบบของโรงเรียนตอบ User ID กลับ)
4. ครูกรอก LINE User ID นั้นให้นักเรียนแต่ละคนหนึ่งครั้ง ผ่านปุ่ม **"🔗 ตั้งค่า LINE ผู้ปกครอง"** ในหน้าจัดการเคส (หรือเรียก API ตรง ๆ ก็ได้ตามด้านล่าง)
5. จากนั้นทุกครั้งที่ครูกด **"✔ อนุมัติ"** ข้อความในแท็บ "📨 แจ้งผู้ปกครอง" ระบบจะพยายามส่งผ่าน LINE ให้ทันที และแจ้งผลสำเร็จ/ไม่สำเร็จกลับมาบนหน้าจอ

ตั้ง/แก้ LINE User ID ของผู้ปกครองผ่าน API โดยตรง:
```bash
curl -X POST http://localhost:5000/api/student/12345/line -H "Content-Type: application/json" \
  -H "Authorization: Bearer <TEACHER_TOKEN>" -d '{"lineUserId":"Uxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx"}'
```

**หมายเหตุความปลอดภัย:** LINE User ID ไม่ใช่ข้อมูลลับเทียบเท่ารหัสผ่าน แต่ก็เป็นข้อมูลส่วนบุคคลที่เชื่อมโยงกับตัวนักเรียนได้ — เก็บเฉพาะในฐานข้อมูลนี้ (ซึ่งถูกกันไม่ให้ดาวน์โหลดผ่านเว็บอยู่แล้วตามหัวข้อด้านบน) และอย่าส่งต่อให้บุคคลที่ไม่เกี่ยวข้อง

### ผูก LINE แบบ Self-service (ผู้ปกครองผูกเอง ไม่ต้องรอครู)
นอกจาก 2 วิธีข้างบน ยังมีทางเลือกที่ 3 คือให้ผู้ปกครอง**ทักแชทเข้า LINE OA ของโรงเรียนโดยตรง** แล้วระบบผูกบัญชีให้อัตโนมัติ โดยไม่ต้องให้ครูกรอกทีละคน

**วิธีทำงาน:** ผู้ปกครองพิมพ์ข้อความรูปแบบ `เลขประจำตัวนักเรียน วันเกิด(ปปปป-ดด-วว)` เช่น `12345 2010-05-15` เข้า OA — ระบบตรวจกับฐานข้อมูล (เงื่อนไขเดียวกับตอนนักเรียน login) ถ้าตรงกันจะผูก LINE User ID ให้ทันทีและตอบยืนยันกลับ ถ้าไม่ตรง จะไม่ผูกอะไรและแจ้งให้ลองใหม่/ติดต่อครู วิธีนี้ป้องกันคนอื่นที่รู้แค่เลขประจำตัว (ซึ่งไม่ใช่ความลับมากนัก) มาผูกบัญชีแทนผู้ปกครองจริง เพราะต้องรู้วันเกิดนักเรียนด้วย

**ตั้งค่า (เพิ่มเติมจากขั้นตอนด้านบน):**
1. สร้าง **Channel secret** (คนละตัวกับ Channel access token) ที่หน้า Basic settings ของ Channel ใน LINE Developers Console
2. ตั้งเป็น environment variable เพิ่มอีกตัว:
   ```bash
   export LINE_CHANNEL_SECRET="ใส่ channel secret ที่นี่"
   ```
3. เปิดเผยเซิร์ฟเวอร์ผ่าน HTTPS สาธารณะ — **ข้อสำคัญ:** LINE จะเรียก webhook ผ่าน HTTPS ที่เข้าถึงได้จากอินเทอร์เน็ตเท่านั้น ระบบนี้ปกติรันอยู่บน LAN โรงเรียนเฉยๆ (ตามหัวข้อด้านล่าง "ใช้จากเครื่องอื่น") จึงต้องมี reverse proxy/tunnel เพิ่ม เช่น [ngrok](https://ngrok.com/) สำหรับทดสอบ หรือ deploy ขึ้นเซิร์ฟเวอร์ที่มี HTTPS จริงสำหรับใช้งานจริง
4. ในหน้า Messaging API ของ Channel ตั้งค่า **Webhook URL** เป็น `https://<โดเมนของคุณ>/api/line/webhook` แล้วกด Verify — ควรได้ 200
5. เปิด "Use webhook" ให้เป็น ON และ**ปิด** "Auto-reply messages" ของ LINE Official Account Manager (ไม่งั้นข้อความตอบอัตโนมัติของ LINE จะไปแทรกกับข้อความยืนยันของระบบ)

จากนั้นเวลาผู้ปกครองแอด OA ครั้งแรก ระบบจะตอบคำแนะนำอัตโนมัติ และเมื่อพิมพ์เลขประจำตัว+วันเกิดถูกต้อง จะผูกให้ทันที — ไม่กระทบวิธีที่ครูผูกเองด้วยมือ (ทำได้ทั้งสองทาง อันไหนทำหลังสุดจะเป็นค่าที่ใช้งาน)

## Deploy ขึ้น Render
ระบบนี้ออกแบบไว้ให้รันบน LAN โรงเรียนเป็นหลัก แต่ถ้าต้องการให้เข้าถึงได้จากอินเทอร์เน็ต (เช่น ให้ผู้ปกครองใช้ฟีเจอร์ผูก LINE แบบ self-service ด้านบน ซึ่งต้องมี HTTPS สาธารณะอยู่แล้ว) [Render](https://render.com) เป็นตัวเลือกที่ตั้งค่าง่าย ได้ HTTPS ฟรีในตัว

**1. เตรียม Git repo** — push โค้ดทั้งหมด (`app.py`, `db_setup.py`, `*.html`, `requirements.txt`) ขึ้น GitHub (**อย่า push `myhealthy.db`** — ควรใส่ใน `.gitignore` เพราะมีข้อมูลนักเรียนจริง และ Render จะสร้างไฟล์นี้เองตอน deploy)

**2. สร้าง Web Service ใหม่บน Render**
- ที่ Render Dashboard → **New** → **Web Service** → เชื่อม GitHub repo ที่ push ไว้
- **Language:** Python 3
- **Build Command:**
  ```
  pip install -r requirements.txt
  ```
- **Start Command:**
  ```
  python db_setup.py && python app.py
  ```
  (รัน `db_setup.py` ก่อนทุกครั้งที่ deploy/restart เพื่อสร้างตารางถ้ายังไม่มี — ใช้ `INSERT OR IGNORE` อยู่แล้วจึงไม่ทับข้อมูลเดิมถ้ามีอยู่แล้ว)

**3. ตั้งค่า Environment Variables** — ในหน้า Web Service ของ Render → แท็บ **Environment** → เพิ่มทีละตัว (key/value):

| Key | ค่าที่ใส่ |
|---|---|
| `SECRET_KEY` | สุ่มสตริงยาวๆ ตั้งเอง (กันไม่ให้สุ่มใหม่ทุกครั้งที่ restart) |
| `LINE_CHANNEL_ACCESS_TOKEN` | จาก LINE Developers Console (ถ้าจะใช้แจ้งเตือนผู้ปกครอง) |
| `LINE_CHANNEL_SECRET` | จาก LINE Developers Console (ถ้าจะใช้ผูก LINE แบบ self-service) |
| `DB_PATH` | ใส่เฉพาะถ้าทำ Persistent Disk ตามข้อ 4 เช่น `/var/data/myhealthy.db` |

ไม่ต้องตั้ง `PORT` เอง — Render กำหนดให้อัตโนมัติ และแอปนี้อ่านค่านั้นให้เองแล้ว

**4. ⚠️ สำคัญมาก — ฐานข้อมูลจะหายถ้าไม่ทำขั้นตอนนี้:** ปกติไฟล์ในเครื่อง Render จะถูกล้างทุกครั้งที่ deploy ใหม่ (ephemeral filesystem) หมายความว่า **`myhealthy.db` จะหายพร้อมข้อมูลนักเรียน/ประวัติทั้งหมดทุกครั้งที่กด deploy ใหม่** ถ้าไม่แก้ปัญหานี้ก่อน
- ไปที่ Web Service → แท็บ **Disks** → **Add Disk** (มีให้ใช้ตั้งแต่แพ็กเกจ Starter ขึ้นไป ไม่มีในแพ็กเกจ Free) → ตั้ง Mount Path เช่น `/var/data`
- กลับไปตั้ง environment variable `DB_PATH=/var/data/myhealthy.db` ตามตารางข้างบน — โค้ดรองรับตัวแปรนี้แล้ว ทั้ง `app.py` และ `db_setup.py` จะอ่าน/เขียนไฟล์ที่ path นี้แทนที่จะอยู่ในโค้ดที่ถูกล้างทุกรอบ deploy

**5. หลัง deploy สำเร็จ** จะได้โดเมนแบบ `https://ชื่อแอป.onrender.com` — ใช้:
- `https://ชื่อแอป.onrender.com/student.html`, `/teacher.html` ได้ทันที
- สร้างบัญชีครูครั้งแรกด้วย `/api/bootstrap-teacher` เหมือนเดิม แต่เปลี่ยน `http://localhost:5000` เป็นโดเมนนี้
- ถ้าจะใช้ผูก LINE แบบ self-service ให้เอาโดเมนนี้ไปตั้งเป็น Webhook URL ใน LINE Developers Console: `https://ชื่อแอป.onrender.com/api/line/webhook`

**ข้อจำกัดที่ควรรู้:** แพ็กเกจ Free ของ Render จะ sleep หลังไม่มีคนใช้ ~15 นาที แล้วรีเควสต์ถัดไปจะช้าไปราว 30-60 วินาทีตอนปลุกเครื่อง (cold start) — ถ้าต้องการให้พร้อมใช้งานตลอดเวลาแบบห้องพยาบาลจริง แนะนำอัปเป็นแพ็กเกจ Starter (แบบเดียวกับที่ต้องใช้เพื่อเปิด Persistent Disk ในข้อ 4 อยู่แล้ว)

## ใช้จากเครื่องอื่น

`http://IP-ของเครื่อง-server:5000/student.html`

ตัวอย่าง:
`http://192.168.1.50:5000/student.html`

หาก Windows Firewall ถาม ให้ Allow Python บน Private Network

## ข้อควรระวัง
ระบบนี้เป็นระบบต้นแบบสำหรับช่วยจัดการงานห้องพยาบาล ไม่ควรใช้ผลจากระบบเป็นการวินิจฉัยหรือสั่งยาอัตโนมัติ ครู/บุคลากรที่ได้รับอนุญาตต้องตรวจสอบอาการ การแพ้ยา และความเหมาะสมก่อนจ่ายยาเสมอ ข้อความแจ้งผู้ปกครองต้องผ่านการอนุมัติของครูก่อนทุกครั้ง ระบบไม่ได้ส่ง SMS/LINE ให้อัตโนมัติ — ครูต้องคัดลอกข้อความที่อนุมัติแล้วไปส่งเองผ่านช่องทางที่โรงเรียนใช้จริง

## ก่อนนำขึ้นใช้งานจริง
แนะนำให้เปลี่ยน SQLite เป็น PostgreSQL หากมีผู้ใช้จำนวนมาก, เปิด HTTPS (สำคัญมากเพราะมีข้อมูลสุขภาพนักเรียน), สำรองข้อมูลสม่ำเสมอ, จำกัด CORS ให้เหลือเฉพาะโดเมนที่ใช้จริงแทน `*`, และกำหนดสิทธิ์ตามนโยบายโรงเรียน
